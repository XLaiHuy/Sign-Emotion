description: Plan or track SignEmo milestones, dependencies and acceptance criteria. Use for repo implementation plans and explicitly requested goals, not automatic goal creation from ordinary tasks.
---

Read `doc/MVP_SPEC.md` and `doc/PROJECT_STATUS.md`. Preserve the chosen PWA-first scope, one owner with Codex, under-3-million cash budget and milestone-based progress without an invented deadline.

Explore existing code/tests before asking discoverable questions. Ask only consequential product/resource questions; record defaults and resolved decisions. Separate locally implementable work from hosted credentials, real Android checks and participant recruitment. Each milestone needs an observable deliverable and verification gate. Do not mark a whole milestone achieved because scaffolding exists.

For authorized implementation, keep the ledger and verification report consistent with actual work. Create a tool goal only on an explicit request to create/pursue a goal; mentioning a planning goal or this skill does not suffice. Do not stop approved work for routine implementation choices, and do not imply permission to send messages, spend money or publish outside the requested deployment scope.
